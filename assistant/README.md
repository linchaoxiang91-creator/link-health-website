# LINK HEALTH 智能服务助手｜公开知识库维护说明

本目录为官网「智能服务助手（知识库试运行）」的**公开、可审阅知识源**。当前采用静态匹配与固定问答，**尚未接入生成式 AI 模型**，因此不产生大模型 API 使用费用。用户输入只在浏览器当前页面处理，不自动发送到服务器或 CRM。

## 如何持续添加内容

1. 将新的服务介绍、项目PPT、医院答复、常见问题及禁用说法提供给网站维护人员。
2. 维护人员先审阅出处、适用范围、版本日期、保密性和医疗风险。
3. 在 `knowledge.json` 的 `topics` 增加/修订条目，每个条目包含：
   - `id`：唯一标识
   - `title`：内部标题
   - `triggers`：访客可能使用的关键词或口语表达
   - `answer`：**已批准可公开**的简短回答
   - `link` / `link_text`：官网详情页（可选）
   - `handoff: true`：必须转人工的事项（可选）
4. 先用测试问题覆盖正常提问、误解问法和边界提问，确认不会错误承诺费用、疗效、资源或预约。
5. 提交 GitHub 后，Pages 自动发布并使知识库生效。修改后通过官网手机和桌面浏览器验收。

## 新资料投喂的保密分级与发布流程（2026-11-05）

**安全前提：本 GitHub 网站仓库及 `assistant/knowledge.json` 为公开内容，任何提交到该仓库的原始数据都应视为可被公众获取，包括后来删除的历史提交。严禁把保密资料、未获授权原始文件或完整客户资料提交到这里。**

| 级别 | 示例 | 可用于官网 AI 客服吗？ |
|---|---|---|
| A｜公开可用 | 已审核官网业务介绍、已核实公开科学资料、服务流程、人工联系方式 | 可以。经事实核对、医疗合规审核并发布脱敏问答后使用 |
| B｜仅内部 | 院方未公开联系方式、供应商报价、利润/采购成本/分润/返佣、谈判条款、合作合同、未公开医疗机构价格及业务策略 | 不可直接投喂网页或公开模型；只能由授权人员内部查看和摘要加工，公开版**不含**具体数额、敏感合作方或可逆推商业信息 |
| C｜特殊敏感 | 客户个人身份、病历、检查报告、影像、联系方式、微信聊天、授权书、支付信息、健康状况 | 不得进入公开知识库、代码仓库、普通第三方大模型或未经同意的 CRM；如需个案工作，先取得合法授权并建立单独权限、最小化访问及保护措施 |

**单份资料的操作步骤：**
1. 接收时仅在当前授权工作环境中审阅，标注出处、日期、权利人和业务敏感等级；标记哪些内容不可公开。
2. 仅抽取可公开业务知识，不复制原始文档、报价单、机密图片、客户记录或内部文件到网站仓库。保密内容即使作为写作背景，也不直接写进答案或训练提示词。
3. 生成待审核的「客户可能怎么问 → 标准答案 → 知识来源与有效日期 → 不可回答内容 → 是否转人工」卡片。
4. 检查是否暗示医生资质、医疗效果、实际合作、预约可用性、治疗价格或“官方认证”等未经证实的事实；不适当内容直接删减。
5. 只把经核准的 A 级摘要写进 `assistant/knowledge.json`。价格、真实排期、合同条件、未确认合作和患者个案一律转人工。
6. 运行发布前检查和实测问题（同义词、诱导提问、越权询价、紧急病症、隐私数据）。检查不能代替人工核稿。
7. 对外发布内容应明确来源（如官方网站公开资料/正规学术研究），变化时及时更新，不做自动“自学习”。

**商业机密的人工转接标准话术：**“涉及具体项目、服务范围、费用或合作安排，需要结合个人需求核实。请联系 LINK HEALTH 人工顾问，我们会在了解情况后提供正式说明。”

**特别提醒：** 当前聊天助手是静态知识匹配，尚未启用模型训练、从文件自动导入或用户对话学习。未来即使接入生成式模型，也必须选择合适的数据处理条款与权限架构，并取得必要授权；不要认为“不展示在页面上”就等于数据保密。

## 内容准则

- 不上传真实客户病历、联系方式、微信聊天、未公开商务条件或内部佣金。
- 不虚构医院与医生合作，尤其不声称美国资源已产生服务案例。
- 不诊断、开药、推荐具体疗法或给出绝对疗效承诺；紧急症状引导就医。
- 不确认未核实的价格、实时预约、能否接诊、签证或医疗项目适应证。
- 回答需注明是一般性服务信息，个人医疗问题由医疗机构评估。
- 客户可直接通过官网人工咨询入口联系 LINK HEALTH，不要求注册。
- 明确保护隐私；如需正式记录线索，未来版本须增加明确同意及访问控制。

## 模型接入路线

下一阶段如接入真实大模型，必须通过安全后端代理（例如独立的 Supabase Edge Function），把密钥保存在后台 Secrets 中，加入访问限额、基础滥用防护、审计和人工转接。**不得把 AI API 密钥写入浏览器前端代码**。涉及个人健康信息时需选择合适的数据处理与合规方案，不直接发送到普通免费推理服务。

## 目前未具备的功能

- 开放式生成式 AI 对话和语义检索
- 管理员在网页里直接编辑训练资料
- CRM 自动建档与客服对话持久化
- 实时医生排期、预约与价格查询

上述功能只能在完成安全设计和配置后上线，不应在前端虚假展示。
